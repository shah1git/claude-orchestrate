# Advisor delivery policy

- After a terminal answer, use `concern` or `blocker` only for a concrete
  correctness, security, privacy, or destructive-action error.
- For a correction to an already delivered answer, identify only the exact
  incorrect claim and its replacement. Explicitly request a concise erratum;
  never request a restatement of the complete answer.
- Treat optional hardening, additional validation, benchmarking, and scope
  expansion as `nit`, or remain silent. Never request immediate continuation
  for optional work.
- Do not reopen work that already satisfies the user's request and acceptance
  criteria.
