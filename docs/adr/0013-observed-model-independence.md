# ADR-0013 — Независимость по фактически использованной модели

- **Статус:** принято
- **Дата:** 2026-08-04
- **Решил:** владелец репозитория
- **Изменяет:** [ADR-0009](0009-native-omp-control-plane.md)
- **Исправляет:** [ADR-0012 §2](0012-model-agnostic-role-slots.md#2-независимость-линз-выражена-слотами-и-точной-проверкой-модели)

## Контекст

ADR-0012 передал замену модели внутри роли механизму OMP
`retry.fallbackChains` и потребовал отклонять Волну, если модель Линзы совпала с
моделью Производителя. Реализация проверяла это до раздачи Линз по
`declaredModel` Производителя и основной модели Линзы.

OMP может применить `fallbackChains` уже во время выполнения `task`. Тогда
фактически использованная модель появляется только в результате как
`observedModel`. Производитель мог переключиться на основную модель Линзы, а
Линза — на модель Производителя или другой Линзы. Проверка по `declaredModel`
такие столкновения не обнаруживала, хотя ADR-0012 утверждал обратное.

## Решение

Слот остаётся единственной единицей маршрутизации. Контур по-прежнему не знает
поставщиков, семейств и конкретных моделей; он сравнивает непрозрачные строки
моделей на точное равенство.

Независимость проверяется в двух точках.

1. Перед раздачей Линз runtime сравнивает фактический `observedModel` каждого
   прошедшего Производителя с моделями, которые OMP разрешил для Линз. Runtime
   также отклоняет раздачу, если две Линзы уже разрешились в одну модель.
2. После выполнения Линз runtime сравнивает их фактические `observedModel` с
   фактическими `observedModel` Производителей и друг с другом. Столкнувшиеся
   Линзы получают `independent_reviewer_unavailable` и повторяются на тех же
   Слотах; их отчёты не поступают в приёмку.

Успешный результат без `observedModel` считается невалидным: без фактического
witness независимость доказать нельзя. `fallbackChains`, назначения моделей и
правила эскалации Слотов этим решением не изменяются.

## Последствия

- Одновременный fallback Производителя и Линзы больше не может пройти
  Линзовый гейт на одной модели.
- Две Линзы не могут пройти Линзовый гейт на одной фактической модели.
- Независимость остаётся model-agnostic: runtime выполняет только точное
  сравнение строк, полученных от OMP.
- Техническое столкновение не меняет Слот и не создаёт запасную роль; повторную
  модель по-прежнему выбирает OMP.

## Отвергнутые варианты

- **Запретить общие модели в `fallbackChains`.** Это переносит политику
  независимости в конфиг, не учитывает текущее состояние поставщиков и требует
  менять назначения моделей. Runtime обязан проверять фактический результат.
- **Считать разные Слоты достаточной независимостью.** Разные роли могут
  фактически выполниться на одной модели после fallback.
- **Проверять только Производителей и Линзы.** Три Линзы образуют один гейт;
  совпадение фактических моделей двух Линз также лишает гейт независимости.
